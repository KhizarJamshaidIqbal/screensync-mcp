THIS PHONE ⟷ YOUR AI

Three pieces. One live loop. Your phone streams frames to a tiny hub on your computer, and your AI agent sees, and acts, through MCP.

Your Phone

The Flutter app captures the screen with MediaProjection: floating bubble, shake-to-capture, or on demand.

MCP Hub

A small Node.js hub on Windows, macOS or Linux (port 3000). Found automatically via mDNS, secured by a bearer token.

Your AI Agent

Claude, or any MCP client that runs local stdio servers, sees frames, reads the UI hierarchy, taps, swipes and types.

01

Install & Pair

Get the app from Google Play, install the ScreenSync hub on your computer, and pair with the Connect-Kit QR code. mDNS finds the hub on your LAN, so there is nothing to type.

02

Go Live

Allow screen capture for the session. The app streams frames over Server-Sent Events with live latency stats (P50/P95, jitter, drops) on the Connection Hero.

03

Let AI Work

Your agent calls MCP tools: grab the latest screenshot, inspect the UI tree, tap buttons, run autonomous UI tests, reproduce bugs, audit accessibility.

Requirements

Screen capture
Android 7.0 or later. No root and no ADB: the app uses MediaProjection after your consent each session.
Device control
Tap, swipe, type and launch app run through ADB from the hub, over USB or wireless debugging.
Hub
Node.js 18 or later on Windows, macOS or Linux (start-hub.bat or start-hub.sh).
Network
Phone and computer on the same network, or the optional Google Drive fallback.

Scan a QR code to pair phone and hub instantly: token, host and port exchanged in one secure step.

Health HUD & Telemetry

Latency sparkline, P50/P95, jitter, dropped-frame counter and sync log: full visibility into the pipeline.

Quality Presets

Stream, Fast and Inspect presets balance latency against fidelity, with a low-latency JPEG mode included.

Optional Google Drive Fallback

Off the LAN? If you turn it on, frames sync through your own Google Drive (bring your own storage) and hybrid mode switches automatically.

Local Capture History

Every capture is cached in a local SQLite gallery with sync state: browse, re-push or clear it anytime.

Engineered for trust & speed

  • LAN-first, token-secured

    Frames travel over your own network with bearer-token auth and never reach EpsolDev servers. The optional Drive fallback uses your Drive, and screenshots your agent requests go to its model provider.

  • About 94 ms median latency

    About 94 ms median (P50) on our LAN tests with the Stream preset. Health pings every 20 seconds keep the link honest.

  • Standard MCP, any stdio client

    Flutter (BLoC) app · Node.js/TypeScript hub · standard MCP stdio + HTTP/SSE. Works with any MCP client that runs local stdio servers.

  • Responsive by contract

    Every app screen is tested at ≤360dp. The adaptive shell scales from small phones to tablets, in light & dark themes.

Questions, answered

ScreenSync MCP is a free Android MCP server by EpsolDev. An Android app streams your phone screen to a small hub on your computer, and the hub exposes it to AI agents over the Model Context Protocol. A Chrome and Edge extension adds your browser tab, so one hub covers phone, desktop and browser.
An Android screen MCP server is a program that gives an AI agent tools to see and use an Android phone through the Model Context Protocol. The agent calls tools such as get_latest_screenshot or control_tap, and the server returns the current screen or performs the tap, swipe or typed text on the device.
Install the ScreenSync MCP app from Google Play, then run the hub on your computer with Node.js 18 or later. Scan the hub's QR code to pair, add the hub to Claude Desktop or Claude Code as a stdio MCP server, and enable USB or wireless debugging so the control tools can tap and type through ADB.
Any MCP client that runs local stdio servers. Claude Desktop and Claude Code have ready-made configs in our setup guide. Cursor and VS Code can run the same hub script with the node command; check your client's MCP docs. ChatGPT's web app only connects to remote HTTPS MCP servers, so it is not supported today.
No root. Capture uses Android's MediaProjection with your consent each session; the control tools run through ADB from the hub. Frames stay on your network, phone to hub with a bearer token, and nothing goes to EpsolDev servers. The optional Google Drive fallback uses your own Drive. Screenshots your agent requests are sent to its model provider.
If you turned on the optional Google Drive fallback, hybrid mode switches to it automatically and frames sync through your own Drive. Captures also queue in the app's local history and push to the hub when a route is available; the dashboard shows the unsynced count.
Yes. ScreenSync MCP is free while it is in active development by EpsolDev, and there is no per-command quota: your agent talks to your own hub. Follow the Goal page for the roadmap.
